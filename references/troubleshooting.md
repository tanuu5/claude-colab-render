# つまずきやすい所

## Cycles が CPU で描いている（1 コマが数分）

- Mac で書いたスクリプトの多くは `prefs.compute_device_type = "METAL"` としている。Linux ではここで TypeError になり、それを受け止めるスクリプトは、何も言わずに CPU に落ちる（作者の作例の `setup_cycles` がそうだった）。
- `gpu_pick.py` を作品のスクリプトより前に `-P` で読ませる。描く直前に GPU に戻すと、ログに `GPU_PICK fixed` が出る。
- `colab_job.py --check` と、ノートブックの 5 のセルが、描く前に確かめる。`GPU_PICK device CPU` なら、GPU が見えていない。

## EEVEE が CPU のソフトウェア描画に落ちる

- EEVEE は、画面の無い Linux では、NVIDIA の EGL（OpenGL）で描く。部品が無いと、ソフトウェア描画（llvmpipe）に黙って落ちる。
- 2026-11 に試した T4・L4・A100 では、部品ははじめから入っていた。無いときは、ノートブックの 4 のセルが、ドライバーと同じ版の NVIDIA の配布ファイル（.run）から、無い物だけを取り出して置く（EGL・GL・OptiX）。ドライバー本体は入れ替えない。
- `__EGL_VENDOR_LIBRARY_FILENAMES` で NVIDIA の EGL を指す（4 のセルが設定する）。

## 頼んだのと違う GPU になる

- G4 を選ぶと割り当て待ちが続き、「選択した GPU タイプは使用できませんでした。現在 A100 に接続しています。」と出て、A100 につながったことがある。A100 は L4 より遅いうえ、ユニットは 4 倍ほど使う。
- job の `accept_gpus` に使ってよい GPU を書いておく。ほかの GPU だと、ノートブックの 1 のセルで、すぐにランタイムを手放す。

## 最初の 1 コマが重い

- Blender を立ち上げるたびに、場面の読み込みと準備がかかる。
  - EEVEE のシェーダーの用意：Linux では 18〜21 秒（Mac は 8 秒）。
  - Cycles の OptiX：T4・L4 では数秒だった。A100 だけ、ランタイムの最初の 1 回に 5 分かかった。
- そのため、区切り（chunk）は 1 回 10〜20 分になるくらいにする。

## 目を離しているときに割り当てられる

- ランタイムが割り当てられるまで、ファイルは上げられない。Drive の許可も、割り当てのあとに聞かれる。
- 割り当てを待つあいだに離れると、許可の画面で止まったまま、ユニットが減っていく。許可されないまま Drive をつなぐ処理が時間切れになったときは、ノートブックはランタイムを手放して止まる（時間切れまでの長さは確かめていない）。
- 混んでいる GPU（G4 など）は、待っても取れないことがある。手が空いているときに頼む。

## タブ・スリープ・時間の上限

- ブラウザのタブは開いたままにして、Mac はスリープさせない。Pro では、タブを閉じると止まることがある（Pro+ にはバックグラウンド実行がある）。
- 1 回のランタイムには時間の上限がある（12〜24 時間）。長い仕事は区切りの印で続きから描けるので、切れたら、もう一度「すべてのセルを実行」する。

## Drive への書き込み

- コマは区切りごとに、手元（/content）で描いてから Drive に写す。Drive に直接書かせると、途中で切れたときに半端なファイルが残り、どこまで描けたかも分かりにくいため（区切りの印は、写し終えてから付ける）。
- 最後にランタイムを手放す前に、`drive.flush_and_unmount()` で、書きかけのファイルを Drive に送りきる（ノートブックの `stop()` がする）。
- Drive の空きを、描く前に確かめる（1080p の PNG は 1 枚 2〜3MB。数千コマで数 GB〜20GB）。

## 絵が Mac と少し違う

- EEVEE は平均 0.04/255 で、ほぼ同じ。Cycles は 0.5/255 で、8 段より違う画素が 1% ほどある（毛の細部）。
- 1 本の動画を分けて描くなら、ひと続きの区間（ショットの切れ目）で分ける。Blender の版もそろえる。

## Python のドライバー・読み込み時に動くスクリプト

- 画面なしの Blender は、何も指定しないと、.blend の中の Python を動かさない（ドライバーの式、読み込み時に動くテキスト）。`blend_check.py` が数える。要るときは、command に `-y` を足す。
